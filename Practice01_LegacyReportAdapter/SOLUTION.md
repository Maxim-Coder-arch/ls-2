# Практика № 1 — решение

## Цепочка вызовов

`Program` создаёт `LegacyReportPrinter`, оборачивает его в `LegacyReportAdapter` и дальше работает только с интерфейсом `IReportExporter`. Адаптер проверяет `ReportDocument` и передаёт заголовок и тело в `LegacyReportPrinter.PrintReport`.

Единственное место, где `Program` знает про конкретные классы, — сборка зависимостей в начале файла. Алиас `ReportExporterAdapter` нужен, потому что пространство имён и класс называются одинаково (`LegacyReportAdapter`), а файл `LegacyReportPrinter.cs` по условию менять нельзя.

## Контракт экспорта

| Вход | Поведение | Обоснование |
| --- | --- | --- |
| `null` вместо принтера в конструкторе | `ArgumentNullException` | Адаптер без принтера не может работать, ошибка должна появиться при создании |
| `null` вместо документа | `ArgumentNullException` | Отсутствие документа — ошибка вызывающего кода |
| Пустой заголовок или заголовок из пробелов | `ArgumentException` | Отчёт без заголовка нельзя отличить от других отчётов, а legacy-формат выводит `===  ===` |
| `null` вместо тела | `ArgumentException` | `null` не является значением, которое можно напечатать |
| Пустое тело | Допустимо | Отчёт только с заголовком — корректный сценарий, принтер выводит пустую строку |

Проверка выполняется до обращения к принтеру, поэтому при ошибке в консоль ничего не попадает. Исключения не перехватываются: решение об обработке принимает вызывающий код.

## Что сохранено без изменений

- `LegacyReportPrinter.cs` остался байт в байт таким же, как в задании.
- Формат вывода (`=== заголовок ===`, тело, `=== END OF REPORT ===`) проверяется тестом на точное совпадение строки.

## Тесты

Запуск: `dotnet run --project LegacyReportAdapter.Tests`. Код возврата `0` означает, что все тесты прошли.

Проверяются основной сценарий, точный формат вывода, многострочное тело, пустое тело, пустой заголовок, заголовок из пробелов, `null`-тело, `null`-документ и `null`-принтер.
